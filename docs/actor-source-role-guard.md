# Original-source actor role guard

Actor writes use `src/okengine/actor_identity.py` through the source adapter in `write_services/integrity.py`. Explicit source victim evidence rejects a fabricated actor profile, while a same-subject original-source adversarial identity or malicious action preserves a genuine actor that was also attacked. Generated profile prose, headings and actor appendices do not establish this source identity.

The affirmative identity grammar accepts descriptive noun phrases such as a North Korean state-sponsored hacking group, Russian-speaking ransomware group, APT group and extortion gang. It requires the complete candidate name, an affirmative copular phrase/article, and an adversarial cue that **modifies the actor-kind noun**: the token immediately before the first actor-kind noun must be a whole-token adversarial cue, or the kind itself must carry one (`threat actor`, `criminal organization`). A cue that modifies some other noun is not an adversarial identity, so a ransomware negotiation team, a threat intelligence group, a criminal defense group, a ransomware recovery team or a hacking prevention team does not describe an adversary. Reverse named-role phrases use the same grammar. Unicode alphabetic descriptors and repeated alphabetic hyphens are supported without a descriptor-count cutoff.

The phrase ends at punctuation, quotation, relative-clause/conjunction boundaries, a new copula/auxiliary, modal, negation or denied-identity marker. It also ends at a relation word that ties the subject *to* an adversary rather than naming what the subject is: a preposition (of, by, from, for, with, against, at, in, on, ...) or a victimization participle (hit, targeted, attacked, breached, compromised, ...). A descriptor token that is (or has a hyphen part that is) a victim, target or defender/service noun (victim, target, customer, client, company, intelligence, negotiation, defense, recovery, prevention, response, research, security, support, detection, ...) also ends it. So `X is a victim of ransomware group Akira`, `X is a company hit by ransomware gang` and `X is the ransomware victim group` keep the victim-organization rejection. The bias is fail-closed: an ambiguous phrase is not an adversarial identity. A cue elsewhere cannot rescue a victim organization. Existing denial, hypothetical, source namespace/readability, alias, severity/CVE and direct malicious-action behavior remains in effect. Missing identity evidence remains unknown.

The actor-kind noun must also **head** the noun phrase rather than modify a later noun. After the kind noun, the subject form accepts only the clause end, a closing mark (comma, colon, parenthesis), a stop or relative word ("that targets hospitals"), a post-modifying preposition ("behind the attack", "with ties to Conti", "in Russia", "since 2020"), a naming or linking participle ("known as", "linked to") or an -ing participle ("operating since 2020"). A possessive ("a ransomware group's victim", "a threat actor's latest victim"), a further noun ("a ransomware group target", "an extortion gang mark", "a ransomware crew hostage"), a victimization participle ("a ransomware group hit by LockBit") or a digit means the subject is that later head, so the victim-organization rejection holds. The reverse named-role form already requires the kind noun to sit directly before `named`/`called`/`known as`/`tracked as`.

The scan is linear in the clause length. A clause that does not contain the complete name is skipped, and the reverse named-role scan indexes article, `by` and break positions once per clause. Because a role phrase cannot contain an article, only the last article before each naming phrase is a candidate, so a long unpunctuated list or table (which collapses into one clause) is not rescanned once per article.

Known recall limits (fail-closed, tracked separately): descriptors whose only adversarial word is outside the curated cue set (hacktivist, cybercrime, espionage, state-sponsored without a following cue) are not recognized, so such a dual-role actor that is also named as a breach victim is still rejected as a victim organization.

Regression evidence includes both source orders, long descriptions, ordinary and unfamiliar names, exact name/cue boundaries, unrelated clauses and denied identities. Actual writer update/Recent activity append fixtures prove maintenance succeeds for supported dual-role actors; existing victim-only append tests prove rejected writes leave bytes unchanged. This document describes the direct guard and does not activate the superseded qualification-platform design.

## Actor identity must be grounded in the cited sources (okengine#1012)

The role guard above only rejects explicit victim grammar. It let the entity-backfill lane mint a sandbox vendor, a hosting provider, a campaign name, a nation-nexus adjective and a package registry as actors: each payload's own prose said "X is a threat group", and nothing tied that claim to the evidence. `src/okengine/actor_grounding.py` is the predicate that does.

- **When it runs.** A model write that creates a `type: actor` page (any letter case), or changes an existing page's type to `actor` (create, update, patch, converge; lane ownership does not exempt a retype). An update to a page that is already an actor is not re-judged. A create is judged only after dedup routing has decided it is a new page.
- **What grounds an actor.** A cited `sources/` page (by path, or an id the id index resolves) that names the subject (title or name, tolerant of separators: `ANY.RUN` = `ANYRUN`; a capitalized name must appear capitalized) and, around that mention, affirms it as an adversary in its own words: the role grammar above, an agent verb ("LockBit claimed ...", "TA488 is exploiting ..."; a past form only with an object, so a headline's "Okta Breached" names a victim), a passive agent ("attributed to X", "targeted by X", "a campaign linked to X"), a named kind ("the Vect ransomware group"), a list under an adversary heading ("ransomware groups Vect and TeamPCP"), a naming phrase ("an operator calling himself Azazel"), a labelled attribution field ("Reported actor: Cl0p"), or a tracker designator (UNC/TA/APT/FIN/TEMP/DEV/Storm-/CL-STA/CL-CRI/UAC/TAG plus a number, or `UNK_<name>`), which names a tracked cluster by construction. A name followed by its kind is read only to the end of its own phrase (punctuation, a dash, or a line break before a new `Field:` line), so "…hit Acme. Ransomware group Qilin…" does not make Acme the attacker. Typographic quotes read as plain ones.
- **Aliases.** An alias is model-written too: it grounds the page only when it shares a distinctive word with the title or name, or in a source that also names the page. Otherwise any actor a source mentions could be borrowed as an "alias" of an unrelated subject. A name that only appears in a headline the body never repeats does not count. Hedged and negated sentences do not count.
- **Curated records.** A curated record (`evidence_role: curated-authority`, operator-owned per okengine#980; `source_kind: reference-data` alone does not count, because a model can set it) vouches without prose only when it is the subject's actor record: titled after the subject and calling itself an actor record. Curated datasets also hold malware families, campaigns, CVEs and ransomware victim rows; those vouch for nothing.
- **Provenance labels** (`sources: [MITRE ATT&CK]`) are not evidence for a model write, because a model can type any label. They vouch only for the deterministic importer of that list (`importer_guard.guard(..., creating=True)`) and in the corpus audit.
- **Bylines.** A page whose name equals its own `publisher` must be affirmed by a source; neither a curated record nor a label can vouch for it.
- **Fail closed.** No source, an unresolvable reference, a name no source contains, or a name no source affirms is a refusal naming the reason (`unsourced`, `no_resolvable_source`, `name_absent_from_sources`, `name_equals_publisher`, `source_defines_non_actor`, `no_source_affirms_actor`).

`corpus_audit` reports the stored corpus with the same predicate: `actor_identity_ungrounded_pages` (WARN, with a per-reason breakdown that adds `headline_title` and `geopolitical_or_nexus_label`) and, apart, `actor_identity_unsourced_pages`.

## Which types are actors (okengine#1020)

Every guard, detector and panel above resolves "is this an actor" through one function, `okengine.actor_types.is_actor_type(schema, type)`, against the governing composed schema. `actor` is always an actor type; a pack adds its own with `role: actor` on the type definition, and a `type_aliases` key mapping onto any of them counts. Callers: the write path (`_actor_admission_reject`, `_actor_grounding_reject`, the entity-backfill sanitizer), `importer_guard`, `corpus_audit`, `review_autoverify`, the active-index generators (`active_view_lib`) and the cockpit actor panels.

- **No back-application.** The engine `actor` type keeps its okengine#846 contract (admission re-runs on every write). A pack-declared type is judged when a page is created as one or retyped to one (and, with okengine#1014, renamed), so declaring a type cannot start refusing ordinary updates to the pages stored before the declaration. The detector still measures them.
- **Names.** A page with no `title` or `name` is looked for by its aliases, then by its slug (`lazarus-group` reads as "lazarus group"). Admission still refuses to create an actor with no title, name or alias.
- **Undetectable, not zero.** `corpus_audit` resolves the targets of the corpus's own `actor`/`actors`/`attributed_to` page references. A type that is not an actor type yet receives at least 3 of them and at least 20% of all resolved ones is reported as `actor_types_undeclared` (a WARN naming the type), and when no actor-type page exists at all the grounding metrics read **undetectable** instead of 0. The type names come from the corpus; the engine names none. `actor` is the engine's own word for the role, not a domain term.
- **Precision.** On one live corpus whose actor sources are agent-written digests, the predicate flags 562 pages of which about 195 are actually wrong (~35%). That is why it refuses only on create, retype and rename, and the detector is a review list (WARN), not a failure.

## Renames, the autoverify hold, and what a subject does (okengine#1014)

- **A rename is judged.** A write that gives a stored actor a name it did not answer to before (a new `title`, `name` or alias, through update, patch or converge) is judged for every declared actor type. Only the NEW names are judged. A new name the deployment already holds as a non-actor (a live vendor, product or malware page) is always judged. Any other new name is the same actor when it shares a distinctive word with a kept name ("Wekby Group", "Krybit ransomware"; generic kind words such as group, APT, ransomware or RaaS tie nothing), or when a cited source binds it to a kept name: a gloss on the kept name itself ("Earth Preta (aka Mustang Panda)", "DoNot APT group (also tracked as APT-C-35, Origami Elephant)"), siblings in one gloss ("Gamaredon (aka Shuckworm, Primitive Bear)"), an alias cue ("X, also known as Y") or a slash. A reporting vendor elsewhere in the sentence ("CrowdStrike analysis of LIMINAL PANDA (formerly LightBasin)") is tied to nothing. A page with no title or name is also called by its slug. An untied new name must ground like a create. A respelling (case, spaces, hyphens, dots: "Fancy Bear" = "FancyBear") or a dropped name is not a rename, and a nameless page always answered to its slug. A stored actor with no resolvable source is unverifiable, so its rename is refused only when the deployment already holds the new name as a non-actor (a vendor or malware page). A declared type's admission checks also run on a rename.
- **`review_autoverify` holds an ungrounded actor.** An actor page whose cited sources do not ground it (`name_absent_from_sources`, `name_equals_publisher`, `source_defines_non_actor`, `no_source_affirms_actor`) stays in the human queue whatever its evidence grade, with the same verdict the corpus audit reports (a curated label vouches). A page with no resolvable source is unverifiable, and keeps the okengine#554/#563 behavior: published with an honest `unverified-no-evidence` stamp.
- **Hedges and claims.** An absence of evidence hedges ("There is no evidence / no indication X attacked", "Nothing suggests X attacked"); "no doubt" does not. `claims`/`claimed` need something after them ("Acme claims." claims nothing) and do not count when the reported clause denies harm ("Acme claims the breach was contained"); a leak-site claim ("Play claims Acme was hacked") still counts.
- **Software and places.** What a subject DOES (its agent verbs, its role clauses, "attributed to X") does not ground it when the deployment's own evidence says it is something else: the source DEFINES it as software ("malware dubbed X", "X, a ... tool", "X is an infostealer"; a name beside a noun, "the Sandworm wiper", names what a group made and does not count), a live non-actor, non-source entity page already carries the name (a `malware` page called RedLine), or the name is one of the pack's `identity_admission.actor.excluded_exact_titles`. An identity statement ("X is a threat group") or a named kind ("the X ransomware gang") still grounds it. The engine names no malware family or country: without that evidence, "RedLine steals ..." and "China targeted ..." still read as an actor, and the nexus label stays a detector reason.
