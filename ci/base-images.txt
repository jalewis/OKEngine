# Base images mirrored into this project's container registry (okengine#751).
#
# WHY: CI pulled these straight from public registries on every job, and Docker Hub's blob CDN
# has broken CI in three different ways -- an IPv6 address with no route (#556), a missing A
# record (#556), and a DNS filter blocking cloudfront.net (#751). A pull-through cache would not
# have helped: every cache fetches its blobs through that same CDN on a miss. Content stored in
# the GitLab registry is served from its own storage, so a job pulling from here never touches
# Docker Hub at all -- not even the first time. The CDN is needed only to SEED this file, which
# `mirror-base-images` does, and which can be retried at leisure rather than mid-pipeline.
#
# COLUMNS (whitespace separated):
#   source    upstream reference, WITH its tag and WITHOUT a digest. Documentation of where the
#             content came from; the job copies by digest, never by this tag.
#   platform  the single platform mirrored. The runner is linux/amd64.
#   mirror    name and tag under $CI_REGISTRY_IMAGE/base/. The tag MUST end in the first 12 hex
#             characters of the digest, so a tag cannot silently come to mean different content.
#   digest    the upstream PLATFORM manifest digest, as resolved by
#             `crane digest --platform <platform> <source>`.
#
# The mirror is byte-identical to upstream. `crane copy` preserves the manifest exactly, so the
# destination digest equals Docker Hub's own published digest and anyone can verify the mirror
# against it. (The earlier python:3.13-slim-trixie mirror from !967 went through docker
# pull/push, which re-serializes: its destination digest 470a5fa... does not match its source.)
#
# Resolved 2026-09-13. python:3.12 was checked against the runner's cached copy: upstream's index
# is still sha256:cd7c412d...., whose amd64 entry is the digest below, so pinning it does not
# change what CI runs.
#
# TO BUMP an image: re-resolve its digest, update both the digest and the tag suffix here, and
# run `mirror-base-images` before merging anything that references the new tag.
